        Reading aloud

        Off by default. With it on, each reply is spoken as it arrives — no need to press 🔊 on every message. Press the button again, or just start typing, to cut it off. There is a 🔊 button under each of your Familiar's messages either way, and neither needs the voice-note microphone.

        Voice notes

        Nothing to switch on. The microphone button sits next to the message box — press it, say what you meant to say, press it again. The words you said appear under the recording before you send, so you can check they were heard right. It all happens on this machine; the first recording offers the one-time download it needs — 158 MB to fetch, 233 MB once unpacked.

        Seeing images (vision)

        On by default, and does nothing until you actually send an image. When on, you can attach a photo in chat and — if the connection can see — your Familiar looks at it directly. Each saved connection above shows a "Can see images?" control: leave it on Auto to let the first image you send settle it, or set it yourself if you know.

        Z.ai Coding Plan? Assign your Coding Plan connection to "Describing images (vision)" above. Your plan's vision allotment runs through z.ai's Vision MCP server (installed automatically the first time it's used, via npx) — images are described with that allotment and your Familiar reads the description, since the coding chat models don't view images directly.

        When on, an image you share that reads as distress can raise your Familiar's concern for you — the same as if you'd typed it. It only ever raises concern, never lowers it, and only your own images count. Turn this off if you share intense imagery (horror, art) that you'd rather it not read as alarm.

        These advanced options read your calendar by running a command-line tool that you install and sign into yourself, once, in a terminal. Proto-Familiar then just runs that command and reads what it prints — it never sees your Google password, and it only reads.

        The usual tool is gcalcli (github.com/insanum/gcalcli):
        
                
          
                  
        1. Install it (its README covers your OS).
          2. 
                  
        2. Run its one-time sign-in once — gcalcli list opens a browser to authorize.
          3. 
                  
        3. Check it works: gcalcli agenda should print your events.
          4. 
                  
        4. Important: gcalcli's own table/agenda output is meant for humans, not machines — the sync needs a command that prints an .ics feed or a JSON array of events (with stable event ids). Paste the exact command that does that for your version into Command, and set Command output to match. If your version can't, a small wrapper script (or the Google account source above) is the reliable route — check "Sync health" below after saving to confirm reads actually parse.
          5. 
                
        
                
        Any other tool that can print your calendar as an .ics feed or a JSON array of events works too — point the Command field at it. (For gogcli specifically, follow that project's own setup; if you're not already using it, the gcalcli route or the Google-account option above are the well-trodden ones.)
        
                
        Fetch the whole window. Many tools only return the next few days by default. Put your tool's date-range flags in the Command and use these tokens — they're filled in with the “Look ahead” window each pull: {dateMin}/{dateMax} (YYYY-MM-DD), {timeMin}/{timeMax} (full ISO), {days}. E.g. gcalcli --nocolor agenda --details=all {dateMin} {dateMax}, or your gogcli read command with its own from/to flags pointed at {dateMin}/{dateMax}.
